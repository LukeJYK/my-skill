# my-skill

A personal collection of AI agent skills, plus an Obsidian vault for browsing them.

This repo **is** `~/.agents`, the directory the [Vercel `skills` CLI](https://github.com/vercel-labs/skills) uses as its global store. There is no copy or sync step: whatever the CLI installs into `~/.agents/skills/` is already in the working tree, ready to commit.

```
~/.agents/                       ← git root (this repo)
├── skills/<name>/SKILL.md       ← skill folders, flat, managed by the skills CLI
├── .skill-lock.json             ← CLI's record of each skill's upstream source
├── <name>.md  maps/  index.md   ← Obsidian notes (generated by .vault/build_vault.py)
├── skills.base  .obsidian/      ← Obsidian table + settings
├── check-skills.py              ← health check (also runs in GitHub Actions)
└── .vault/build_vault.py        ← regenerates the notes

~/Desktop/my-skill  →  symlink to ~/.agents (open it in VS Code / Obsidian, run git here)
```

## Set up a new machine

```bash
git clone git@github.com:LukeJYK/my-skill.git ~/.agents
ln -s ~/.agents ~/Desktop/my-skill
cd ~/.agents && npx skills update -g      # optional: pull latest from upstream
```

`~/.agents` must not exist before the clone (move it aside if it does).

## Everyday use

```bash
cd ~/.agents
npx skills add <owner/repo> -s <skill> -g -a universal -y   # install
npx skills update -g                                         # update all from upstream
python3 .vault/build_vault.py                                # refresh the notes
python3 check-skills.py --quiet                              # health check
git add -A && git commit -m "..." && git push
```

- `-a universal` writes only to `~/.agents/skills` and never touches `~/.claude/skills`. Always pass it; otherwise the CLI reuses the last selected agents.
- Install from the upstream `owner/repo`, so the lock records it and `update` can pull from it.
- Your own skills: create `skills/<name>/SKILL.md` directly. They have no lock entry, so `update` leaves them alone.

## Rules

1. **Run `npx skills` from `~/.agents`, never through `~/Desktop/my-skill`.** The CLI compares paths as strings. Passing a path under the Desktop symlink as the source (e.g. `npx skills add ~/Desktop/my-skill/skills/foo -g`) makes it delete the destination, which is the source, and the skill is gone. Tested 2026-11-24. Git, VS Code and Obsidian through the symlink are fine.
2. **Keep `~/.agents` a real directory.** Don't replace it with a symlink to somewhere else; the same string-compare problem applies.
3. **Keep `skills/` flat.** The CLI hardcodes `~/.agents/skills/<name>` and would copy categorised skills back out to flat paths. Put structure in the notes (`maps/`, tags, `skills.base`), not in folders.

## Health check

`python3 check-skills.py` checks frontmatter, broken links, script syntax and lock-file consistency for every skill; see the docstring for the full list. GitHub Actions runs it on every push and every Monday ([.github/workflows/skill-health.yml](.github/workflows/skill-health.yml)).
